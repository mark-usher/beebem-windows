Hard Disks

BeebEm supports emulated SCSI, SASI and IDE hard disks. You can only have one of either SCSI or IDE hard drive enabled at a time.

There are some preformatted ADFS disk images in the DiscIms folder. The disks can be used in Model B (you will need to add a suitable ADFS ROM to the ROM configuration, see below), B Plus or Master 128 mode. To use the disk images enable hard drive emulation on the Hardware menu and press A + F12 to boot in ADFS mode (ignore the error for drive 4 if in Master mode). The hard disks then appear as drives 0 to 3. Floppy disks can still be accessed as drives 4 and 5.

You need to use the ADFS 1.30 ROM (BBC) and ADFS 1.50 ROM (Master) to use the SCSI interface, and the ADFS 1.33 ROM (BBC) and ADFS 1.53 ROM (Master) to use the IDE interface. HADFS 5.30 and later use the IDE interface.

There are 4 10MB pre-formatted ADFS SCSI disk images in the DiscIms folder (the scsi?.dat files). There are 4 4MB blank IDE drive images in the DiscIms folder (the ide?.dat files).

There are some demo tunes in scsi0.dat which you can listen to with the PLAY program.

There is also the sasi0.dat file which is a Torch Z80 hard disc image (see the Torch Z80 section).

You can use the Hardware → Select Hard Drive Folder menu option to select an alternative folder containing hard disk image files. The folder should contain scsi?.dat, sasi?.dat or ide?.dat files, together with corresponding .dsc files.

Use the Options → Save Preferences menu option to save the setting to the BeebEm Preferences.cfg file.

Note that if you replace the scsi?.dat files, the scsi?.dsc files may also need changing to configure the size of the hard disk image. Bytes in the scsi?.dsc file used by BeebEm (with offsets starting at 0):

  • Byte offset 13 = number of cyclinders (high byte)
  • Byte offset 14 = number of cyclinders (low byte)
  • Byte offset 15 = number of heads

The number of 256 byte sectors in the hard disk image is calculated as:

Sectors = heads * (cyclinders high byte * 256 + cyclinders low byte) * 33

SCSI drive descriptors

The SCSI drives are emulated as Pi1MHz's BeebSCSI emulates them. Each drive can have a scsi?.cfg file, in the hard drive folder, which gives its identity and its SCSI parameters: the INQUIRY data the host sees, the block size, and the SCSI mode pages a real drive reports (current values, which bits MODE SELECT may change, and factory values). A drive with no .cfg file is described by defscsi.cfg, from the hard drive folder or the user data folder, which is copied to the drive's own scsi?.cfg the first time a host changes its parameters (with MODE SELECT or FORMAT). A drive with a .dsc file and no .cfg file takes its geometry from the .dsc file, as before.

The shipped defscsi.cfg describes every byte of its values in its comments, and is the best starting point for a drive of your own. The files are the same as Pi1MHz's, so a drive and its .cfg file can be moved between BeebEm and a Pi1MHz. The capacity of a drive is cylinders × heads × sectors per track × block size, from its mode pages (or from the size of the image, see SCSI Drive Geometry below); an image smaller than that grows as it is written.

The drives are started by a START UNIT command, or by the first READ or WRITE, as on Pi1MHz: until then TEST UNIT READY reports that the drive is not ready.

SCSI drive controller

The Hardware → SCSI Drive Controller menu selects the controller behind the Acorn SCSI host adaptor, for all the drives. It decides the commands the drives answer, how they report errors and how FORMAT lays out a track:

  • Mixed (Pi1MHz): the default. Every command is answered, with mode pages and the Adaptec drive parameter list. ADFS, SuperForm and the Acorn FileStore all work.
  • Adaptec ACB-4000 (MFM): as the Acorn Winchester 110, 120 and 130 and the Level 3 file server's board. No INQUIRY or mode pages, so a FileStore finds no drives behind it.
  • Adaptec ACB-4070 (RLL): as the ACB-4000, with the RLL board's sectors per track.
  • SASI (Xebec, DTC, OMTI): as the ACB-4000, keeping the sectors per track the drive's .cfg file gives.
  • SCSI Drive (own controller): a drive with its own controller, such as the Rodime RO652 in an Acorn FileStore E20: extended sense, mode pages as the drive's .cfg file gives them, and new geometry taking effect at the next FORMAT.

SCSI drive geometry

The Hardware → SCSI Drive Geometry menu selects what to do with a drive .cfg file that has no geometry page (page 4, or page 0 except under SCSI Drive): Auto (the default) works out the geometry from the size of the image file; From the .cfg File Only makes nothing up, and the drive refuses a MODE SENSE of that page, as a drive without it would.

Both settings are saved in the preferences file (SCSIDriveController and SCSIDriveGeometry). For the details of the .cfg files see Pi1MHz's documentation, github.com/dp111/Pi1MHz (SCSI Drive Descriptors and Configuration).
